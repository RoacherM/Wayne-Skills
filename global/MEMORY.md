# MEMORY.md — 个人工作习惯与跨项目纠偏记录

本文件由 `AGENTS.md` 按场景按需引用，记录我的个人偏好与历史踩坑模式。仅在进入对应类型的任务时读取相关小节。

## 界面与原型

- **先交可打开的真实数据原型**：讨论或设计界面时，第一步直接交能打开看的原型（尽量用真实数据），明确画出它在窗口里的位置和它展示谁的数据，不先交长篇文字方案。
- **严格贴合参考图与原词**：给了参考图就按参考图的形式画（如只有拓扑方块和连线，就不自创「分轮」或侧边文字栏），用我的原词定单位与主角。
- **极简自解释，零夹带**：只做明确确认的节点与交互，不顺手加筛选/缩放/跳转按钮；顶栏和空状态优先靠图形、SVG 图标和纯数字自解释，不写教学式说明句、文字胶囊或兜底假摘要。

## 编码与验证

- **修慢流程改逻辑，不加数值门槛**：评审、测试或构建慢时，先找出哪一步在逻辑上重复或放错了位置并删改它，不用行数、时间占比这类死板数字门槛去压症状。
- **单功能外部调用直接跑真实验证**：新增或修改外部服务调用的功能，离线单测通过后当轮直接跑 3–5 次真实调用验收，不要停下来请示；只有高成本批量评测或长耗时全量跑分才先报预算等确认。
- **小事自己查，异构模型做独立审查**：几个文件或几页文档能确认的事主会话自己做，只有重度调研、海量文档处理或独立代码审查才起子 Agent。起独立审查前先查模型别名实际映射（如 `env | grep ANTHROPIC_DEFAULT`），确保审查者与作者属于不同模型家族且使用干净上下文。
- **评估库先读官方文档**：介绍、选型或接入第三方库时，先读官方文档再用源码印证；让我「带过一遍」时给足输入、输出、关键参数、适用场景和可运行示例，不只列标题级要点。
- **配置与提示词变更集中列表**：新增或修改了配置项、默认值、限制阈值或 Prompt 文本时，在回复里用一张紧凑表列出（`值 | 原因 | 文件`）。

## 文档与沟通

- **直白人话，通用术语直说**：结论先行，用自然连贯的句子讲清结论、根因和取舍，少堆碎列表；通用工程术语直接用，只解释自造词或团队外不共享的概念，不为单次纠正矫枉过正。
- **新上下文直接落进交付物**：补充背景材料是为了推进当前交付物时，回复直接以更新后的交付物为主体，只简短说明改了哪里和为什么，不把背景复述成喧宾夺主的现状报告。
- **内部草案保持草案感**：写内部讨论稿或草案时直白、允许粗糙，不为了整齐做成满篇平行表格、口号和咨询报告腔。
- **OKR 用标准写法**：O 一句话写终点状态，KR 一句话写可验证结果加日期；具体执行步骤放进任务列表，不塞进 KR，也不自创结构。
- **规则与卡片统一骨架**：写多份规则或角色卡先定同一份结构骨架，靠结构消掉特例；消不掉的例外一条一句，不堆 corner case。

## 环境与配额

- **可复用工具交付成独立仓库**：做可复用工具时交付成带完整安装说明的独立 Git 仓库，不直接改本机全局配置当交付物。
- **默认复制安装，查清软链真身**：安装工具或配置默认用复制而非软链（除非明确要求软链）；判断两个配置路径是否同一份文件前，先查符号链接与 `realpath`。
- **复刻环境按本机清单装齐**：在容器或新机器同步常用环境时，以本机正在用的清单为准把依赖一并装齐，不自作主张替我筛掉哪个「用不上」；远端装软件或起常驻进程前先用一两句话说清方案等确认。
- **额度紧张时薄编排**：我说额度/token 紧张时，主控只做编排与最后验收——把读写长文、中间核对和多步执行串成单脚本交给指定的便宜模型一次跑完，不在每步之间反复唤醒主控。
